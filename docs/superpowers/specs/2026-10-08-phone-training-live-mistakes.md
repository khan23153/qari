# Phone ASR training and live confirmed mistakes

The user selects a surah and recites it. The selected Quran text supplies the matcher reference. Independent audio recognition supplies the evidence; expected verse text is never an oracle recognition prompt. Confirmed incorrect words must be visible in red while tracking continues through later words. Unreached Hifz text remains hidden, all ayah markers remain visible, and review continues to summarize mistakes and unreached words. Uncertain ASR output must not be treated as a confirmed user mistake.

Use the existing robust Whisper training pipeline, fresh tiny-base weights recovered from the user's own Kaggle outputs, encoder-only FP32 adaptation, and correctly labeled phone/amateur speech with bounded noise augmentation. Preserve decoder vocabulary and language/task token IDs. Keep the user's confirmed 36.92-second Al-Fatihah recording as a release-test fixture, not a training sample. Evaluate silence and unrelated Al-Ikhlas speech against the selected Al-Fatihah reference.

The first run is a private Kaggle GPU pilot with one epoch. Dataset preflight must reject missing/ambiguous audio, oversized clips, incompatible labels, and train/eval overlap. The notebook saves baseline and candidate metrics plus a release decision. Launching training is authorized by the user's request; promotion to the live backend requires real-phone/negative tests and the current backend guards to pass. UI changes are independently verified and delivered in an APK.

Known RetaSy speakers are held out from known training speakers. TLOG rows with namespaced unknown speaker IDs remain training-only and are counted as unverified; they cannot establish full speaker-disjointness. Fresh phone tests and the VPS benchmark remain mandatory, and no automatic model promotion is allowed. A live recognition gap can advance the cursor but is not red: only a high-confidence spoken one-word substitution bounded by a later confirmed match supplies confirmed-mistake evidence.
